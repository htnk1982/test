# PDRM 採用2段 一括入口 v1

日付: 2026-09-05

## 現在の採用判断

利用者が3曲を総合し、Note-Sub v0.2.1＋HFTC v0.1を合格と判断した。聴感採用は確定し、Song1の4条件比較は中止する。この入口はその採用規則を、毎回A/Bを選ばず実行するための追加アプリである。

## 最初の1回だけ

ZIPを展開し、`pdrm_finish.cmd` と `PDRM_Finish_v1` フォルダを、現在動いている `round9_lab.cmd` と `.venv` があるフォルダへ置く。従来のNote-Sub/HFTCファイルや本番runtimeは上書きしない。pip・新しいモデル・診断ツールの追加実行は不要。

## 使う操作

`pdrm_finish.cmd` をダブルクリックし、仕上げたいステレオWAV/FLACを選ぶ。複数選択できる。44.1/48/88.2/96 kHz、0.5秒以上を扱う。

この入口が行うのは、音量の準備 → Note-Sub → HFTC → 最終音量調整だけ。HarmonicElasticity、前段ノイズ除去、リミッターは加えない。HarmonicElasticityをすでに適用した音へ使う場合も、追加2段を未適用の状態を入力する。前回試聴の共通ピーク保護込み経路を再現するものではない。

処理後は出力フォルダが開く。`LAST_RUN.md` に各入力の結果フォルダが載る。各RESULTに以下を保存する。

- `FINISHED.wav`: 原サンプルレートのステレオFLOAT WAV。
- `FINISHED_320kbps.mp3`: 確認用MP3。
- `完了.md`: 音量・ピーク・実行状態。

既定の出力先は `%LOCALAPPDATA%\PDRM_Local_Render_Engine_v1\accepted_finish`。音声やローカルパスを外部へ送信しない。全曲音声を常時メモリに載せず、既存のチャンク処理を使う。

## 音量の扱い

−14 LUFSは必達値にしない。入力を一定ゲインだけで−14 LUFSへ調整したときにピーク余裕がなくなる曲は、最初の全曲基準を下げる。基準は `min(-14, 入力LUFS + (-2.5 - 入力TP推定))`。Note-Subの入出力ラウドネス目標だけをその値へ接続し、追跡閾値・追加量上限等は既定値を保持する。接続中に変更した目標は呼出終了時に必ず戻す。HFTCのゲイン曲線と係数も既定のままである。

最終PCMは−1.5 dBTP以下、MP3復号後は−1.0 dBTP以下を数値推定で検査。必要なら最後も全曲共通ゲインだけで下げる。ピークの形を変えるリミッターやクリッパーは使わない。したがって一部の曲は−14 LUFSより小さくなる。

これは新しい入出力接続規則であり、以前の3曲試聴音源のビット同一再生成や、前処理込み音質の同一性を保証するものではない。今回の採用判断を再び保留に戻す意味ではない。

## 保存・再開・二重適用の防止

原音は上書きしない。入力・コード・設定・ライブラリ・ffmpegの識別子ごとに仕事を分ける。同じ元入力を同じ設定で再実行すると、完了済み出力を検証して再利用する。中断後は確定済みNote-Sub出力とHFチャンクを再利用する。

出力ディレクトリ内の音、既知の処理済み名称、登録済み出力と同じ復号PCMは再入力を拒否する。単純なファイル名変更でも、同じ保存先の登録が残っていれば拒否する。ただし別保存先への変更、登録削除、MP3からの再変換等まで全自動識別できるわけではない。**完成音を再入力せず、元入力からやり直すこと。**

数値条件が満たせないファイルは失敗として記録し、無断の強度調整や別処理で救済しない。複数選択時はそのファイルを未出力として次のファイルへ進む。低域追加不要の状態は既存Note-Sub規則に従う。内部のJSONは利用者に提出を求める資料ではない。

## 適用範囲

3曲総合による個人制作向け採用。医学的疲労改善、全リスナー・全曲での保証ではない。通常運用の入口は両段ONで固定。追加聴感選択は不要。具体的な不具合が出たときだけ、その現象を修正対象にする。

新規コードは一括入口とその試験、起動cmd、ガイド、専用CI。既存DSPと本番pdrm_engine/pdrm_runtime/pdrm_operator_labは変更しない。現在の67件回帰に入口17件を加える。これは機械接続の検査で、利用者の採用判断を再審査する工程ではない。
