# PDRM AUTO v3.4.1 — ミリ秒換算修正版

旧v3.4の長文脈救済には、128msを128秒として扱う単位換算漏れがありました。この版はそれを修正します。詳細はCONTEXT_MS_BUGFIX_20260906.mdを参照してください。

## 操作

ZIP全体を旧版と別のフォルダへ展開し、PDRM_AUTO.exeを起動してください。PythonやFFmpegの追加インストールは不要です。起動表示は3.4.1-auto-exeです。

WAV／MP3のLUFSとTP上限を指定して、元のWAV／FLACを選びます。初期値はWAV −12 LUFS／−2 dBTP、MP3 −14 LUFS／−2 dBTP。既存のv3.4設定は引き継ぎます。

元ファイルと同じフォルダのprocessedへ元の名前.wav・元の名前.mp3を保存します。WAVは24-bit PCM、MP3は320kbpsです。元音源は変更しません。

以前の完成音を更新する場合のみ「既存のPDRM出力を退避して、同じ名前で作り直す」を選びます。管理記録とハッシュが一致する音源をバックアップしてから更新し、手動編集済みの音源は置換しません。

## 自動処理

各ピーク段は定数ゲイン → OPPO → 音響上NotFeasibleのときのみ通常リミッター。I/O異常、非有限値、整合性異常、キャンセル等はフォールバックで隠しません。数値条件に届かない完成音は公開しません。

救済文脈は128／256／512／1024ミリ秒です。対象区間と境界保護が候補幅に入らなければ次の幅へ進み、最大候補でも不可能なら通常リミッターへ戻します。実際の処理幅はOPPO_CONTEXT_PLAN表示と処理記録に残ります。

修正前の救済結果との波形一致は保証しません。短窓OPPO・Note-Sub・HFTC・HarmonicElasticityの処理規則と保護閾値は変更していません。

## 作業ファイル

曲ごとの成功／通常失敗で大容量の作業音声を削除します。強制終了時の同じ版の途中結果は再開に使用します。別版の同じ入力に紐づく旧キャッシュは開始時に除去し、他曲の原音・完成音を消しません。

## 配布

EXEだけでなく_internal／LICENSES／SOURCESを含むフォルダ全体を配布してください。発行者のコード署名はありません。保護機能を無効にしないでください。

## 検証の読み方

仕様試験は修正前の不具合を実際に検出し、修正版の物理単位を検査します。SOURCE_TEST_RESULTS.jsonは回帰試験、EXE_SMOKE_RESULTS.jsonはWindowsでの実行結果です。これらは全楽曲の自然さや全曲10倍高速化の保証ではありません。
