# PDRM AUTO v3.4.1 — 救済範囲のミリ秒換算修正

## 不具合と判断の訂正

旧v3.2〜v3.4の共通処理 `_context_bounds` は `round(ms * sr)` としており、ミリ秒から秒への `/1000` が欠落していた。v3.4もこの共通関数を呼んでいた。これは不具合であり、品質保持のために残す対象ではない。

48 kHz、300秒の音源で128 ms指定が6,144,000フレーム（128秒）となることを再現した。正しい値は6,144フレーム（0.128秒）。短い試験音源では全曲長へ切り詰められ、誤りが隠れていた。旧版への出力一致は正しさの証明になっていなかった。

従来の「長文脈は128〜1024 msで処理する」「保護条件を維持しているので品質も維持」という全体的な説明は、この不具合を含む救済経路には成立しない。通常のOPPOが成立して救済を呼ばない経路とは区別する。

## 修正

- 共通関数で `round(ms * sr / 1000.0)` を用いる。v3.4ラッパーだけに隠すのでなく、共有の不具合箇所を修正する。
- 選んだ文脈で失敗区間と境界ガードを含められない場合、文脈を勝手に拡大せず次の指定値を試す。全候補で無理なら音響上のNotFeasibleとして既存AUTOへ返す。
- 前後の境界保護、元ファイル範囲、整数フレームへの丸めを検査する。
- 実行記録へ指定msに加えて実際のms・フレーム数・元サンプルレートを記録する。
- 版と処理識別子を変更し、バグを含む古い中間結果を新結果として再利用しない。成功済みの旧完成音は勝手に上書きしない。

Note-Sub、HFTC、HarmonicElasticity、短窓OPPOの核、周波数重み・自然さゲートの閾値、リミッターの設定は変更しない。既存のGUIの4数値、同名processed保存、曲単位のキャッシュ削除を維持する。

## 品質と性能を分ける

救済の参照範囲が変わるため、救済が発動した音源の出力やAUTOのOPPO／リミッター選択は変わり得る。修正版を旧版とビット一致させることは要求しない。旧版の音源をすべて破損扱いにもせず、救済の有無で影響を区別する。

広すぎた文脈がRMSやパーセンタイルの母集団を変え、局所的な変化を過小評価していた可能性がある。ただし、利用者の各曲で実際に聞こえる変化が生じていたかは未確認。

最初に正しい時間幅を回復し、その後に修正済み版を速度改善の基準にする。誤った128秒処理を128msへ戻した効果と、正しい計算を効率化した効果を混ぜない。入力長による切詰め・その他の処理時間があるため1000倍の速度向上とは主張しない。全曲10倍高速化は未達・未検証。

## 追加する仕様試験

128ms・48kHz=6144フレームを外部仕様の数値として直接検査する。44.1/48/88.2/96kHzと128/256/512/1024msの組合せ、1秒〜30分の仮想音源長、曲頭／曲末、短いファイル、指定幅に入らない区間、上限超過、実際の救済呼出しと記録、救済なし経路の一致を含む12件。

旧コードで失敗することを先に確認済み。修正版で12件が通過。既存試験を含む実行結果とWindows配布EXEの検証は同梱のSOURCE_TEST_RESULTS.json／EXE_SMOKE_RESULTS.jsonを参照し、それぞれの完了状態を区別する。
