# PDRM 配信用一括実行 v2 — 使い方

## 出力

| ファイル | 全曲LUFS-I | True Peakの扱い | 形式 |
|---|---:|---|---|
| MASTER_12LUFS.wav | −12.00（許容±0.03 LU） | 最大−2 dBTP以下 | 24-bit PCM WAV |
| LISTEN_14LUFS.wav | −14.00（許容±0.03 LU） | マスターから約2 dB下げる。通常最大−4 dBTP以下 | 24-bit PCM WAV |
| LISTEN_14LUFS_320kbps.mp3 | −14 WAVから符号化。復号後±0.10 LU内を確認 | 復号後最大−2 dBTP以下を確認 | 320kbps MP3 |

−12と−14の指定を両立させるため、マスターと試聴用を別ファイルにしています。−2 dBTPはピークの上限であり、全曲を必ず同じ最大ピークにする指定ではありません。低いピークを無理に引き上げません。

WAVは入力のサンプルレートを維持します。入力は44.1/48/88.2/96 kHz、ステレオWAV/FLAC、0.5秒以上。MP3は44.1/48kHzで、88.2/96kHz入力では48kHzへ変換します。無音・非有限値などは完成扱いにしません。

## 導入

ZIPを展開し、次の2つを、現在動いている `.venv` や `round9_lab.cmd` があるフォルダへコピーします。

- `pdrm_distribution_v2.cmd`
- `PDRM_Distribution_v2` フォルダ全体

以前の `pdrm_finish.cmd`、`PDRM_Finish_v1`、本番runtimeは置換しません。新しい方のcmdを使ってください。pip、doctor、selftestの再実行は不要です。既存環境のFFmpeg（またはimageio-ffmpeg付属バイナリ）を使い、実行時にダウンロードしません。

## 操作

1. `pdrm_distribution_v2.cmd` をダブルクリックします。
2. PDRM未適用のWAV/FLACを選びます。複数曲を同時選択できます。
3. 完成音を保存するフォルダを選びます。

完了すると選択したフォルダが開きます。曲名＋識別子のフォルダ内に上の3ファイルと `完了.md` が入ります。全曲の結果一覧は `LAST_RUN_Distribution_v2.md` です。一曲が失敗しても残りの曲を処理し、未完了を一覧へ残します。

入力フォルダと同じ場所も選べますが、元音声は上書きせず、別の曲別フォルダを作成します。同名でも中身が違う音源は別の識別子になります。既存の完成ファイルが人手で変更された場合は上書きしません。

## 処理経路

```text
入力WAV/FLAC
  → HarmonicElasticity（amount=0.105、quintic_scale=0.30、4倍処理）
  → 共通ピーク整形・内部基準−14 LUFS／最大−2.5 dBTP
  → Note-Sub v0.2.1
  → HFTC v0.1
  → 配信用ゲイン＋必要なピーク制御
  → MASTER_12LUFS.wav（−12 LUFS、最大−2 dBTP）
  → 一定ゲインのみで LISTEN_14LUFS.wav
  → この−14 WAVからMP3を符号化・復号検査
```

Note-SubとHFTCの音符判定・補完量・高域制御は採用済みのままです。新しい入口ではHarmonicElasticityとピーク制御が有効です。v1の2段専用版にはこの2つは入っていませんでした。

今回の共通ピーク制御は、4倍処理、5ms先読み、80msリリース、適応リリース、遅延補償を明示したFFmpeg alimiterです。自動メイクアップは無効。必要のない場合は一定ゲインだけにします。目標への反復は同じ元入力からやり直し、処理済み候補へのリミッター重ね掛けではありません。

前回の3曲比較に使われた、具体設定が記録されていないピーク処理の完全再現を主張しません。今回新たに許可されたピーク処理を、再現可能な設定として実装した版です。

## 保護と記録

ピーク制御後の波形を4倍・8倍補間で再測定し、大きい方を判定に使います。True Peakは数値推定で、認証機器の保証ではありません。WAV保存後とMP3復号後にもLUFS・ピーク・長さ・チャンネルを検査します。

LUFSとTPの両方が条件内に入らなければ、低い音量のファイルを−12と表示して公開せず「未出力」にします。調整は最大8回、入力ドライブ上限36dBです。検査の合格は音質の独立した再承認ではありません。

中間音声とチェックポイントは選択先の `.pdrm_work_v2` に保存します。数分の曲でも複数の中間WAVを使うため、1曲あたり数GB程度の空きを確保してください。中断後は元音源を再選択します。完成済みの同一ジョブは再加工しません。

完成音や既にHE/Note-Sub/HFTCを適用した音を新規入力しないでください。検出済み出力は名称・PCM記録で拒否しますが、別環境で改名・加工された全ての音の処理履歴を自動判定できるわけではありません。

## 旧仕様との区別

採用済みのNote-Sub＋HFTCの判断は撤回しません。ただし今回は利用者指定により目標音量・ピーク制御・入力段が変わっています。新ピーク処理が必ず旧試聴版と同じ質感になると保証するものではありません。数値を合わせた実際の加工量は `RUN_REPORT.json` に自動記録されます。追加JSONの提出は不要です。

## API根拠

- FFmpeg公式 `doc/filters.texi` の alimiter: 先読み、attack/release、ASC、自動レベル、latency、2x/4x処理の記載。
- SciPy公式 `signal.resample_poly`: 多相FIRによるアップ/ダウンサンプリングと境界条件。

これは実装APIの根拠であり、聴き疲れ軽減の因果証明ではありません。
