# PDRM — EXE統合の残課題・実装契約 v1

日付：2026-09-09  
確認した基準commit：`9237e8e4f98f31318394592d06da401a49be9aea`  
状態：ソース確認に基づく統合設計。新DSP・新EXE・新たな音質試験の完了報告ではない。

## 1. 判断と完成条件

次の開発単位を、独立LABの追加から、既存処理をつなぐ全曲の音楽的処理計画器へ変更する。処理器の種類を増やすことを主目標にしない。

完成条件は、元WAV/FLACの選択から、発音/成分の自動抽出、役割観測、問題診断、量決定、最終WAV/MP3の検査、同名保存、曲単位クリーンアップまで、開発者による発音時刻の手入力なしで完走すること。

低域の新制御は旧Note-Subの後に追加せず、その判断・生成経路を置換する。HE・HFTC・OPPOの採用済みDSP本体は初回統合で変更しない。バグや実装上の単位不整合まで保存するという意味ではない。

ここまでの了承は開発方向・到達点の了承として扱い、合成試験の成功を、任意の実曲に対する音質承認やモデルの配布承認に読み替えない。

## 2. ソースにより確認した不足

| 箇所 | 現状 | 統合に必要なもの |
|---|---|---|
| `event_decay_v39.Event` | 時刻、anchor、対象帯域、関連帯域、role/familyを呼出側が供給 | 任意の全曲から候補と根拠を自動生成する入口 |
| 相対減衰の時間条件 | 最短0.8秒、最長8秒。anchorとtailの文脈が必要 | 短い低音の発音を別経路で扱う。対象外を正常と呼ばない |
| スペクトル解析 | 12kHz、4096サンプル窓、240サンプルhop | 約341msの窓と20ms更新を区別。hopを発音検出精度とみなさない |
| `event_decay_v39.calibrate()` | 同じrole/family/相対帯域配置で、4独立群以上の局所正例が必要 | 既存の弱い役割レビューから実際に利用可能な校正への橋渡し |
| `event_groove_v37.process_event()` | 手渡しイベントの同一基音を補強。量は固定LAB予算 | 全曲イベント抽出、実曲の量校正、物理枝との由来照合 |
| `auto_conditioned_v34.run()` | 旧Note-Subの解析・生成・強度選択を呼ぶ | 新計画器への差替え。旧生成器との二重実行禁止 |
| `natural_finish_v34._runtime()` | ロック下で共有モジュール参照を一時差替え | 初回は曲ごとの直列処理。共有状態差替えをさらに増やさない |
| 検証 | Boundary39に173件のソフトウェア試験と18合成ケースの記録 | 実モデル推論と実曲自動処理、最終AUTO、実EXEを結んだ試験 |

0.8秒未満の発音を扱わないのは相対減衰LABの仕様範囲であり、全パイプラインが短音非対応と断定するものではない。ただし、この分岐一つを短音も含む全低域の制御器として出荷することはできない。

## 3. 最初の統合候補の範囲

含める：KEEP、過大な低域ヒットの整理、局所的な低域占有の整理、支持された相対減衰の修正、校正が成立した同一基音補強、既存HE/HFTC/最終AUTO、保存・後始末。

初回の出荷条件から外す：新規octave-down、存在する基音が不明な合成、全楽器の完全な意味理解、新しい中高域エキサイター、HFTC全面改修、巨大な汎用嗜好モデル、10倍高速化、GPU/NPU必須化。

同一基音補強の量校正が未完了なら搭載済みと称さない。修復のみの限定評価版を作る場合は範囲を明示し、従来の有効な補強まで無言で失わせない。研究用評価版と一般公開版の完成条件を分ける。

## 4. 二つの信号経路と同一性

原音解析枝：
```text
元ファイル → 全曲の候補抽出 → 必要区間の役割観測 → 音楽イベント台帳
```

物理音声枝：
```text
元ファイル
  ↓
既存HarmonicElasticity
  ↓
既存AUTO前段
  ↓
新低域coordinator〔上の台帳を参照〕
  ↓
共通の変更予算で低域差分を描画〔旧Note-Subと置換〕
  ↓
既存HFTC
  ↓
既存AUTO最終WAV
  ↓
MP3専用枝・符号化・復号検査
  ↓
保存後検査 → 原子的な公開 → 曲単位掃除
```

原音解析は位置・音程・役割の証拠を提供する。適用量・干渉・余裕はHE/AUTO後の実音声から再測定する。非線形な前処理後は、同じLUFSでも局所波形が同じではない。

原音と物理枝でhashが異なることは正常。hash照合を外したり、観測のhashを差し替えたりして接続しない。

必要なインターフェース：
- `SourceIdentity`：元ファイルhash、復号PCM識別子、レート、長さ、チャンネル。
- `RenderSnapshot`：物理音声hash、親SourceIdentity、処理段階、config/code hash。
- `TimeMap`：原レートの整数フレーム、SRC比、補償遅延、端点丸め規則。
- `Evidence`：観測器/モデル版、支持時間、役割、不一致、音程と対応の根拠。
- `MusicalPlan`：症状、対象、操作、許容量、保護対象、校正版、未対応理由。
- `Outcome`：技術的成功と、改善/未解消/保留を別々に持つ。

## 5. 全曲イベント抽出と時間設計

短時間の立ち上がり検出と、十分な周期を必要とする低域の音程・倍音分析を分業する。単一の約341ms窓に両方を任せない。長窓と短窓を同じ原音時計へ対応づける。

関連成分には、共通の立ち上がり、音程軌跡、倍音関係、包絡の追随、役割の安定、他音との競合を使う。同じ役割・同時発音だけで同じ音符と断定しない。非調和な打撃音を無理に倍音系列へ当てはめない。

拍情報は文脈に使い、発音位置は動かさない。長い音を短くすることも、全アタックを強くすることも目的にしない。短くても過大なヒットは別分岐で扱う。

先に軽量な全曲解析を行い、操作候補を含む区間を前後文脈つきで観測する。近接区間はまとめ、窓端の証拠不足には重なりを持たせる。候補の取りこぼしを別に検査し、未観測を解析済みと数えない。

## 6. 実際に成立する校正経路

現行v39は厳密な局所正例を要求する。全曲役割コメントはそのままでは局所正例条件を満たさない。この不足を隠して、合成参照を本人の嗜好で校正済みとしてはならない。

校正系は三層で設計する。
1. 原音内の同種イベント。ただし全曲に同じ欠点がある場合は正解とみなさない。
2. 役割・発音形態・相対音程が近い参照群の弱い事前情報。
3. 明示的な局所評価が存在する場合、その強い保護/修正条件。

役割コメントから自動抽出した区間は弱いラベルのまま保持する。空欄を正例にせず、ある楽器への好評を別の楽器へ転用しない。弱い情報を使う校正器は別の版・ラベル種別とし、v39の厳密条件を満たしたように装わない。

暫定境界は、原版/故障コピーと既知の実曲の対照で検証する。しきい値は自然さの真理ではなく、実測で改訂する設計値である。

利用者への大量な局所ラベル付け要求を標準の成立条件にしない。一方、資料にない主観判断を捏造して不足を埋めない。同一コーパスのleave-one-outを独立した最終評価と呼ばず、原版と故障コピーは同じグループに置く。

## 7. 複数処理の適用量を一つにまとめる

ヒット、占有率、相対減衰、基音補強を順番に最大適用しない。同じ物理snapshotから候補を作り、共通の変更予算で裁定する。

同じ時間・帯域で削減と加算が自己相殺しないよう、発音禁止/保護条件、既存過剰の修正、不足が残る場合の同一基音補強の順に決める。

減算マスクは共通の時間・周波数表現で重複を裁定する。複数1.5dB処理を無言で足し上げない。マスク上限だけでは実音の量・位相干渉を保証できず、描画後の混合音で再測定する。

有限個の候補と無加工を元の同じsnapshotから作る。修正目標を満たし保護条件を破らない中で最小の変更を選ぶ。未達なら予算内の代替を評価し、最大処理を成功と呼ばない。

## 8. 最終AUTOとの相互作用

HE/HFTC/OPPOのコードが同じでも低域修正で後段のピーク・LUFS・制御量が変わる。コード凍結と完成音の質感保持は別の試験とする。

同じ原入力・同じHE/前段から低域修正の有無を分岐し、HFTC→AUTO→MP3まで通す。既知の誤生成を含む旧Note-Sub結果を無条件の正解にしない。

GAIN_ONLY/OPPO/LIMITERの実動作、理由、最終LUFS/TP、符号化後の結果を記録する。低域の役割推定失敗を通常リミッターへ回して修復成功と呼ばない。利用者の目標は勝手に下げない。

完成音で対象の実改善、非対象への影響、アタック、声、曲末、ステレオ、原音不変を別に確認する。平均スコアで局所破綻を相殺しない。15kHz超の主観評価を今回の資料で承認済みとせず、新しい高域改造へ範囲を広げない。

## 9. モデルの配布条件と依存環境

HDEMUCS_HIGH_MUSDBは公式資料でMUSDB-HQ訓練セットによる学習が明記されている。Demucs READMEはMITを表示する一方、作者のIssue #327コメントは重みをMIT対象外・科学目的と説明している。

本資料は個別利用の法的結論ではない。しかし当該checkpointの配信用利用・再配布が確認済みとも扱えない。特定の重みと用途の根拠を確認するか、許諾の明確な重みに替え、同じ観測タスクで再評価する。別ダウンロードや形式変換を許諾の代用品にしない。

モデルmanifestには配布元、hash、前処理/推論版、条件の根拠、許容用途、対応機能を持たせる。モデル変更には校正と回帰を伴わせる。一般利用向け配布物に未確認の研究重みを混ぜない。

TorchAudioはmaintenance phaseにある。「最新版なら動く」という依存解決にせず、Python/Torch/TorchAudio/NumPy/SciPy/FFmpeg/PyInstallerとモデルの組をWindowsで固定する。既存I/Oはできるだけ維持し、依存更新と音質改修を同時に混ぜない。

## 10. Windows・SSD・実行時間

配布は従来同様、起動EXE一つが見えるフォルダ型ZIPを基本とする。Python/pip/手動ステム書出しを利用者に要求しない。権利確認済みモデルは管理された場所に置き、曲処理中に無断ダウンロードしない。

GUIとworkerを分離し、モデルはworker内で再利用する。初回は曲ごとの直列処理。multiprocessing使用時はGUI生成前のfreeze_support、子プロセス回収、キャンセル、FFmpeg終了を実EXEで検査する。

10倍高速化は再開しない。ただし新しい観測込みの実行時間は測定する。旧版で許容された速度を新経路でも維持できると未測定で宣言しない。

全4ステム×全曲をWAVに溜めない。観測波形は特徴抽出後に解放し、小さな特徴と計画だけを保存する。全曲float64配列を何本も保持しない。

モデル/設定、job領域、完成音、旧出力backupを分離する。
- 成功：完成WAV/MP3と記録を照合・公開後、その曲の所有する中間物を削除。
- 通常失敗/キャンセル：大きな中間音を削除し、小さな原因記録を保持。
- 強制終了：次回lock/所有manifestを確認し、resumeまたはそのjobだけの掃除。
- 完成音backupはキャッシュではない。作業掃除で消さない。

開始前と途中に容量/権限を確認する。作業先だけでなく最終保存先とbackup分も計上する。モデル不在を音響的な不成立と混同して旧生成器へ戻さない。

## 11. 完了と保留を分ける

| 状態 | 意味 | 動作 |
|---|---|---|
| KEEP | 支持範囲でその操作は不要 | 無加工。全音質正常とは断定しない |
| CORRECTED | 検証可能な目標を達成 | 対象・操作・数値を記録 |
| PARTIAL | 予算内で改善したが未達 | 改善と未解消を分けて表示 |
| ABSTAIN | 役割/関連付け/校正の支持不足 | 根拠のない生成をしない。良好率に含めない |
| TECHNICAL_FAILURE | I/O、破損、非有限値、hash不整合等 | 中止。リミッターで隠さない |
| CANCELLED | 利用者の中止 | worker回収と所有領域の掃除 |

新機能を要求する通常モードでモデルが欠落・破損・用途未確認なら開始前に停止する。解析なしの縮退結果を自動で新方式成功にしない。安全な音量整合だけを別機能として残す場合は範囲を明示する。

GUIはWAV/MP3のLUFS/TP、ファイル選択、進捗、キャンセル、既存出力退避を中心に保つ。役割ごとの閾値やモデル選定を利用者へ押し付けない。

## 12. 実装順と完了条件

| 順序 | 作業 | 終了条件 |
|---|---|---|
| 1 | source/physical/time-mapとcoordinator | 旧Note-Sub二重呼出しなし。全KEEPなら新低域差分0 |
| 2 | 全曲イベント抽出、観測scheduler、関連付け | 手入力時刻なし。短音/曲端/境界で証拠と音がずれない |
| 3 | 弱いレビューの校正経路と操作別量 | 好例保存と負例修復を両立。常時バイパスで合格しない |
| 4 | 共通予算とAUTO/MP3結合 | 二重補正なし。実動作するOPPO/limiterを含む完成音で確認 |
| 5 | Windows評価EXE | Python未導入・ネット遮断・通常権限で実モデル込み一曲完走 |
| 6 | バッチ/保存/掃除/再開/最終聴感 | 容量累積や破綻なし。内部比較を絞り必要な聴感判断だけ残す |

モデル用途・再配布とWindows依存の確認は順序1と並行する。完成間際に発見して全設計を戻さない。

試験は(1)単体契約、(2)原版/故障コピー、(3)実曲自動処理、(4)実EXE運用の四層。過去173件は実曲の神経観測やEXE試験の代わりではない。利用者へ全曲再試聴、大量JSON、全面的な局所ラベル追記を毎回依頼しない。

## 13. 今回の状態

この変更は統合設計文書のみ。新DSP実行、神経推論、全曲再処理、自動試験、新EXEの成功は主張しない。ローカルcontainer/Pythonは応答せず、根拠確認は接続repo、提供仕様、公式資料で行った。音源・レビュー・参照プロファイル・重みを今回のcommitへ追加していない。

次の中心実装は新しいLAB効果ではなく、全曲のMusicalPlanを生成して旧低域入口を置換するcoordinator。ここまでの成果を一曲の経路にまとめる。

三つの検討視点：音響側は好ましい発音/質感の保持、推定側は弱いラベルと不確かさの保存、運用側はモデル条件と容量/公開整合。共通方針は統合器へ進むこと。残る論点はモデル、校正、実音の適量。現時点で利用者に新たに要求する判断はない。
