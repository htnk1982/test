# PDRM：EXE化の現在地と次工程

確認日：2026-09-10
状態：現在地の説明。今回、新しい音声処理・テスト・EXEビルドは実施していない。

## 結論

まだ「完成した音響処理をEXEにまとめれば完成」という段階ではない。EXEとして動く技術確認はQA版で済んでいるが、実曲用の自動判断と、利用者向けの機能統合が残っている。

次の作業の中心は、新しい処理器の研究を増やすことではなく、実曲評価用EXEに必要な既存機能の統合と実曲での確認である。

## 現在地

| 項目 | 確認済みの範囲／残件 |
|---|---|
| 広域・狭帯域の共同処理 | LAB実装済み。原音の許可と前処理後の必要量を区別し、重複する減算を単純加算しない |
| Windows EXE化 | QA専用バイナリで合成音5ケースを実行し、ソース版と完成WAVの復号PCM・MP3全バイト・処理経路が一致 |
| 実曲での音楽的判断 | 発音・関連成分の自動対応と、レビューに沿った適用量の校正が未完了 |
| 同一基音の補強 | 加算処理を共同予算へ接続する作業が残る |
| 利用者向けアプリ | 採用モデルの用途確認とWindows実推論、GUI・processed保存・強制終了再開・長時間バッチの新経路への統合が残る |

315件のソフトウェア試験やQA EXEの成功は、任意の実曲での音質合格を意味しない。従来の配布版に保存・GUI機能が存在することと、新経路でもその接続を検証済みであることは別である。

## 次工程の整理

1. 実曲の自動判断と未接続処理を共同処理へつなぐ。正常な持続と不要な居残りを区別し、基音補強を無言で省かない。
2. 既存音源・レビューを使い、好ましい部分の保存と問題箇所の修正を、最終ピーク処理後の完成音まで確認する。GUIや保存機能の統合は並行して進められるが、内部の実曲検証を利用者の大量再試聴へ置き換えない。
3. 用途確認済みモデルを含む実曲評価用EXEとして、指定LUFS/TP、同名WAV/MP3、原音保護、中断・清掃・連続処理を検証する。

既存のHE・HFTC・OPPOをこの統合のために大改造しない。機能を省く限定版を作る場合は、その範囲を明示し、当初の要件を満たした完成版とは呼ばない。

## 進捗説明の訂正

「実EXEで動いた」という成果を強調すると、残作業がGUIへの組込みだけに見える。しかし、残る中核は実曲に対する判断と量決定であり、軽微な梱包作業ではない。新しい指標や試験件数の追加を、その完成の代わりにしない。
