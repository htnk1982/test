## 1. 実装した入口

`integrated_finish_v40.run_lab()`は既存HE → 既存AUTO前段 → 新低域coordinator → 既存HFTC → 既存AUTO最終 → WAV/MP3保存後検査、を直接呼ぶ。

このLAB経路では旧Note-Subの音符抽出・イベント生成・音声描画を呼ばない。試験中にその3関数を呼ぶと例外になる仕掛けで確認した。既存の配布GUI/EXE入口はまだ切り替えていない。

新しい入口は、明示したplanner、校正識別情報、LAB許可を要求する。今回のplannerは工程検査用のengineering_fixtureであり、元音源から自動で最適処理を推定するものではない。planner欠落を暗黙のKEEP成功に変換しない。

## 2. 原音と物理処理音の対応

`integration_contract_v40.py`は元ファイルのバイトhash、復号PCM hash、音声形式、原音と前処理音の親関係、処理レシピhashを保持する。

元音の観測とHE/AUTO後の物理音声はhashが違って当然であり、その対応をRenderSnapshotで表す。hash検査を外さない。時刻は整数フレームと有理数のSRC/遅延対応で保持する。44100→48000、長時間位置、半サンプル、128ms=6144frames@48kHz等の検査を含む。

これは誤接続や処理中の変更を検出する契約であり、悪意のあるコードに対する来歴証明や署名ではない。

候補区間を8秒以下のcoreと前後contextへ整理するスケジューラも追加した。ただし、区間の自動発見やステム観測完了は別工程。coreと周辺contextを混同せず、未観測を健康判定に数えない。

## 3. 共通予算と描画

`lowend_coordinator_v40.py`は、同じ物理snapshotからの候補だけを受け取る。今回対応した既存Boundary36の共通低域/中低域枝について、重複する減算要求は合算せず最大深さにまとめる。例: 同一枝の1.5dB要求二つを3dBにしない。

既存レンダラーを変更せず、全曲先頭からの共通制御を、前後文脈付きの分割I/Oで一度だけ描画する。分割位置の違いと既存一括描画の一致は最大差許容2e-12で検査した。チャンクごとの音量合わせはしない。

全KEEP時は低域段の入力ファイルをバイト単位で保存する。実行要求と実際のPCM変更は別々に記録する。保存した計画をJSONから戻す際のtuple/list不整合を最終化前に修正し、CANDIDATE/KEEP_SUPPORTED/ABSTAINの三状態を再読込して全経路を実行した。

同一基音加算、狭帯域・相対減衰の共通予算アダプターは今回まだ接続していない。未対応操作を広いEQへ勝手に変換せず拒否する。全LAB処理器を統合済みという意味ではない。

## 4. 実行で確認したもの

既存LAB173件 + 新規69件 = 242件。Windows/Ubuntuとも failures=0、errors=0、skipped=0。

約2.6秒の合成ステレオ音と、明示した工程試験用計画を使用した。HE・HFTC・AUTO・PCM24・MP3符号化・復号検査は実際の既存コードを実行。神経モデル推論や本人音源の処理は今回行っていない。

全KEEPの完成WAVは、同じHE/AUTO/HFTC/最終AUTOから低域段だけを省いた別の明示的比較経路と復号PCMが完全一致した。旧Note-Sub込みの従来マスターとの一致ではない。

## 5. 保存・掃除・異常時

新LAB入口は、呼出しごとに独占所有する一時jobを作り、成功後・通常失敗・キャンセルでその作業物を削除する。元音、既存processed、backupは受け付ける削除対象に含めない。試験では中間WAVの残留なしを確認した。

原音/物理snapshotの変更、非有限値、計画改変、I/O異常、欠落planner、キャンセルは停止し、旧音楽生成器や別プランへ逃がさない。既存結果のhash/ファイル集合を照合して再実行をスキップし、改変済み結果は上書きしない。

今回の出力先は独立したINTEGRATION_LAB結果フォルダ。本番processedへの同名公開、GUI/worker接続、強制終了後のresume/回収は未接続。既存配布版が持つ機能まで新入口で完成したとは言わない。

## 6. 保持したものと残るもの

基準から15ファイルの一致を検査。既存HE、HFTC、OPPO、ミリ秒換算修正、旧入口、公開/掃除、本番GUI/EXEを変更していない。
