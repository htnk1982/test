# PDRM 音符追従型サブベース補完 — 実験版 v0.1

## 今回の配布物

新しい低域レイヤーを作るDSP、ローカル起動用CMD、診断ランチャーです。以前の測定専用ツールではありません。採用Cを上書きせず、Cと追加処理版をWAV／MP3で出力します。音声と本番runtimeは公開GitHubへ送信しません。通信・追加モデルのダウンロード・pip実行をしません。

**これは新機能の研究試作です。合成信号でのテストと、実際の曲で音程・効果が正しいことを分けます。市販製品やD.O.I.の非公開処理の再現、SOTA到達、全曲への無条件適用は主張しません。**

## 操作

1. `note_sub_lab.py`、`note_sub_launch.py`、`note_sub_lab.cmd`の3ファイルを、いま動いている`round9_lab.cmd`と同じフォルダへコピーします。
2. `note_sub_lab.cmd`をダブルクリックし、今回試聴したRound9フォルダ内の`manifest.json`を選びます。manifestのドラッグでも起動できます。
3. 最後に表示される`SUB_REPORT.json`の場所を確認します。初回はこのJSONを提出し、処理対象時間と誤推定の兆候を確認します。環境の再インストール、selftest／doctor／受入試験の再実行は不要です。

原則の出力先は `%LOCALAPPDATA%\PDRM_Local_Render_Engine_v1\note_sub_lab\sub_...\RESULT` です。

## 出力

- `CONTROL_C.wav`：入力Cのファイルコピー。
- `SUB_AUGMENTED.wav`：実験出力。成立区間がなければCそのまま。
- `DELTA_SUB_FLOAT.wav`：実際に採用した追加低域だけ。全曲レベル調整前のモノラルFLOAT WAV。
- `BLIND_TEST/LISTEN_A_320kbps.mp3`, `LISTEN_B_320kbps.mp3`：同じMP3経路の2候補。
- `PDRM_Note_Sub_BLIND_MP3.zip`：上記2本だけの無圧縮ZIP。
- `SUB_REPORT.json`, `SUB_REPORT.md`：量、ピーク、レベル、漏れ、見送り理由。
- `NOTE_EVENTS.json`：提案イベントの音高・追加周波数・時間・包絡。採否と倍率はSUB_REPORT側も参照。
- `REVEAL_AFTER_LISTENING.txt`：対応表。音を評価するときは先に開かない。

0.1版の追加対象は30〜65Hzです。30〜65Hzの基音補完、または60〜130Hz付近のベースの1オクターブ下を候補にします。110Hz以上は新規に狙わず、その帯域への漏れを検査します。比較条件は全曲−14 LUFS。プラットフォーム一般のマスタリング推奨値という意味ではありません。

## 実装の範囲と、前の仕様に対する段階分け

今回実装したのは、2mixの低域に一つの音高が十分優勢な区間を使う最初の検証可能な経路です。二つの分析帯域で周期を照合し、上方倍音の整合、音高の連続性、打撃音に似た急変、既存サブの量で候補を制限します。グローバルキーに音を固定せず、半音・微小なチューニング差を測定値のまま扱います。全曲の分析を終えてからイベントをつなぎ、周波数軌道を積分して追加波形を描画します。

**ベース／キックを楽器として識別する学習済みステム分離、和声認識、曲のキー表示は未実装です。** この違いを隠して「ベースを完全分離した」とは扱いません。二つの帯域で一致しても、同じ誤りをする可能性があります。周期性スコアは正答確率ではありません。

検証対象として残るのは、実曲での誤音率、適用できる区間割合、追加した低音が演奏の一部に聞こえるかです。純サイン波のベースとキック、重なる複数低音、短い経過音、急なスライドは、0.1版では保留しやすくなっています。適用ゼロを「低域は十分」と読み替えません。

## 変更しないもの

Cを分離ステムで置き換えません。CへHarmonicElasticityを再実行しません。元のキックを加工しません。全帯域リミッタ、広域EQ、高域倍音追加、ステレオ拡張、キー主音のドローンを追加しません。追加波形は採用した時間区間内に限定し、発音前へ予測で書き込みません。イベント前後の内側にフェードを置くため、元のアタックをサブで作り直す処理でもありません。

最終的には `output = common_gain * (C + delta_sub)` です。LUFS合わせによる中高域の一様な音量変化は別に記録します。中高域までサンプル完全不変とは言いません。

## 再現性と障害対応

入力・コード・設定・ライブラリ版をjob識別に含めます。8秒単位の分析とレンダリングを逐次保存し、ハッシュが一致する完了部分は再利用します。2秒ごとの表示は生存と直近の工程更新時刻を分けます。SQLiteは使いません。同時起動はOSロックで拒否します。最終出力は検査後にRESULTディレクトリへ公開し、既存の別結果は上書きしません。

正常に終わった同じjobは再処理しません。異常時は表示された`SUB_FAILURE.json`または起動ログを保存します。繰り返し試さず、その1ファイルを提出してください。通常の例外を3回記録したjobは停止します。強制終了後の未完了分は再開対象です。`CANCEL`ファイルをjob内に置いた場合は次の工程更新で停止し、再開前にそのファイルを取り除きます。

## 工学上のゲートと音質判断

工学上の初期値は、PCMのTP推定−1.5dBTP以下、MP3復号後−1dBTP以下、全曲合わせによるゲイン変化0.5dB以内、追加レイヤーの110Hz以上エネルギー比−35dB以下などです。これらは品質の普遍的閾値ではありません。量は1、0.5、0.25の有限候補から条件を満たすものを選び、満たさなければ追加しません。

- `RENDERED_EXPERIMENT_NOT_QUALITY_APPROVAL`：低域を描画し数値条件を通過。聴感承認ではない。
- `NO_ELIGIBLE_ADDITION`：十分な候補が得られずCを保持。低域十分の証明ではない。
- `NO_ADDITION_WITHIN_GATES`：候補はあったが数値条件内では採用できずCを保持。
- `FAILED_NOT_PUBLISHED`：今回の処理は未完了。途中の音を比較用成果として使わない。

## 技術的参照

McLeod/Wyvillのnormalized square difference系の音高推定、およびSciPyのsignal処理を参考にした独自の狭い実装です。MPMそのものの完全実装とも、モノフォニック手法が複音ミックスで普遍的に使えるとも主張しません。

- P. McLeod, G. Wyvill, A Smarter Way to Find Pitch, ICMC 2005.
- https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html
- https://github.com/csteinmetz1/pyloudnorm （係数取得と全曲LUFS照合に使用）

学習済み分離を導入する場合は、この描画・保護層とは別に、モデル配布・実機負荷・誤推定を検証して接続します。今回はそれを導入済みとは扱いません。
