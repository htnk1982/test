# PDRM Note-Sub Lab v0.1.1 — イベント監査と次版の修正条件

日付：2026-09-05
状態：提出JSONと配布版ソースを照合した診断・修正仕様。DSP変更、音声の再測定、レンダリング、試聴は行っていない。

## 1. 対象と証拠の範囲

利用者が提出した NOTE_EVENTS.json と SUB_REPORT.json を対象とする。原音声、イベント配列の全文、入力ハッシュ、個人PCのパスは本書に転載しない。

コード照合対象：commit `2c9002fa842ce9d130c3c47df87246e871e3909a` の `PDRM_Local_Render_Engine_v1/note_sub_lab.py`。主に `sub_frequency`、`analyze_frame`、`make_events`、`event_wave` を確認した。

JSONはプログラムの判断記録であり、元のベース演奏の正解ラベルではない。保存された周波数軌道が滑らかでも、正しい楽器・音程を認識した証明にはならない。採用時点で安定した軌道を選別していることにも注意する。

## 3. 具体的に見つかった分割問題

隣接する二つの採用イベントにおいて、推定f0の中央値は約43.78Hzから約87.26Hzへ変わる一方、生成先の中央値は約43.78Hzから約43.63Hzへ変わるだけだった。二つのイベントの間隔は20msで、設定された分析hop一つ分。生成先の境界の実値も、ともに約43.7Hzである。

`make_events` は、生成先 `sub_hz` が連続していても、推定元 `f0_hz` のフレーム間変化が75centを超えると分割する。`sub_frequency` は30〜65Hzなら同じ周波数を返し、それより高い候補は条件内で半分にする。したがって、推定元のオクターブ切替が、生成先はほぼ同じなのにイベントを分ける構造になっている。

この観測は区間設計の修正根拠になる。ただし、元の演奏が実際にオクターブを移った可能性、同音再アタックだった可能性、異なる低音源だった可能性は、JSONだけでは排除できない。生成先が同じという理由だけで二つを無条件に接続してはならない。

各イベントの位相は独立に選ばれている。ただし全イベントにフェードがあるため、位相値が異なることをそのままクリック発生や実際の位相不連続の証明にしない。問題は、確認された一つの持続音を扱う場合にも、判断上の分割で包絡・位相を再開始し得ること。

## 4. 短いイベントとフェードの組合せ

設定は片側60msの内向きフェードである。今回の最短イベント120msでは、立ち上げと立ち下げが全時間を占め、フェード包絡が1のまま続く区間はない。160msでもその区間は40msにとどまる。

19イベントに対するフェード区間の合計は19×0.120=2.280秒、イベント時間3.760秒の約60.6%。フェード包絡が1になる区間の合計は1.480秒。ただしこれはソースコードの包絡から求めた幾何学的な時間集計であり、可聴時間や一定振幅の時間を意味しない。イベント内部の振幅配列も変化する。

滑らかな接続を意図した処理でも、許可区間が短く分断されると、持続した低音を補うより短い膨らみを作る構造になる。実際に不自然に聞こえたと断定したわけではない。

対策は一律にフェードを短くすることでも、イベントを長く引き伸ばすことでもない。元の発音・休符・再アタックに対応する境界を先に求め、音符内の振幅制御とイベントの存続を分離する。

## 5. 分断の修正だけでも足りない

SUB_REPORTでは、weak_periodicityが6,821フレーム、transient_or_boundaryが3,387フレーム、全理由合計10,843フレーム。この二つで約94.14%を占める。理由は早期returnで一つだけ記録されるので、独立した原因の寄与率ではない。

今回の認識方式では、音高の解釈へ進めない場所が大部分を占める。19イベントのつなぎ方だけ修正しても、その前に捨てた観測を回復したことにはならない。上流のベース候補抽出・音高追跡も改修対象である。

また `make_events` はamplitudeが0のフレームで無条件にイベントを閉じる。これにより「音が存在しない」「認識できない」「音は認識できるが低域が十分なので足さない」が、イベント終了という同じ結果になる。音符の存続と追加必要量を混同している。

## 6. 次版の分離設計

### 6.1 音の追跡

分析用ベース候補から、音高候補・上方倍音の整合・発音・減衰・休符・再アタックを読む。既存の低域が十分で追加量が0でも、観測上の音符は追跡する。前後の文脈で短い推定の揺れを判断する。十分な観測がない区間へは、前の音を自動延長しない。

学習済み分離などを導入する場合も、分離波形でC全体を置換せず分析用途に限定する。その選定・導入・実機試験は本書の実施範囲外。

### 6.2 生成先の選択

推定元f0と生成先の音高軌道を別々に管理する。同じ生成先となるオクターブ候補の切替だけを、音符終了の十分条件にしない。一方、本当の別音符・休符・再アタックまで結合しない。元のキーへの一律な量子化や、主音ドローン追加には戻らない。

### 6.3 足す量の判定

既存低域量、キック等との重なり、ピーク余裕を基に、音符内の追加量を制御する。「足さない」と「音符が終わった」を別状態にする。音量ゲートを認識の正しさの代用にしない。

### 6.4 波形描画

確認できた同一音符の内部では位相積分を継続する。短い追加量0区間がある場合も、必要に応じ内部位相は保持できる。ただし、内部状態を保持することと、未知区間で音を出すことは別。発音境界と各音符の長さに合う包絡を設定する。Cへの再処理・上書きは禁止。

## 7. 次版で追加すべき受入例

1. 同一の持続音を正解として用意し、推定元だけが1オクターブ切り替わる試験。生成先が同じなら、推定の切替だけで包絡・位相を再開始しない。
2. 同音の再アタックと本当の休符を含む試験。生成先が同じでも、別音符を勝手に接続しない。
3. 音高は安定しているが既存低域量だけが上下する試験。追加量の0通過を音符終了と混同しない。
4. 元の音高が既知のベースへキック・和音・高域の打撃を混ぜる試験。単独のきれいなベースだけで性能承認しない。
5. 原音が不明な実曲では、適用率だけを合否の目的関数にせず、誤音・休符への追加・短い分断・数値ゲートと聴感評価を分けて記録する。

これらは修正仕様と試験設計であり、今回実行してPASSした試験ではない。

## 8. 今回の判定と次の工程

- 採用Cは維持する。v0.1.1のサブ追加版は実用採用を保留する。
- 下方低域を補う手法そのものの棄却ではない。
- 追加強度や許可率を増やす前に、分析用のベース候補抽出、音符追跡、追加量、波形描画の責務を分ける。
- 2つのJSONで確認できる今回のイベント監査は閉じる。同じ判定のために別のJSONをさらに要求しない。
- 今回はコード照合・集計・修正仕様の記録まで。新DSP、本番設定変更、新音源の生成は行っていない。
