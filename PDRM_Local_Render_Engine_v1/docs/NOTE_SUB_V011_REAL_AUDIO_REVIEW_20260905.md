# PDRM Note-Sub Lab v0.1.1 — 実音源レポートの判定

作成日：2026-09-05
対象：利用者から提出された SUB_REPORT.json（note-sub-lab-0.1.1）
範囲：提出JSONの集計、配布版ソースの該当処理の確認、次の判別行動の決定。
実音声の聴取・再測定、新DSPの実装、再レンダリング、本番設定変更は今回行っていない。入力音源、個人PCのパス、提出JSONの全文は本書へ転載しない。

## 結論

レポート上は処理が完了し、追加レイヤーと比較用音声が出力された。しかし、追加対象は全216.842秒のうち19区間・合計3.76秒、全曲時間の約1.734%にとどまる。

これは「サブ補完が曲全体の低域不足を改善した」という証明ではない。現在の方式は、この素材に対して追加を許可できた時間が非常に短い。実用採用は保留し、既存Cを比較基準のまま維持する。

小さな適用率だけから、正しい適用率の数値目標や聴感上の無効を決めない。一部だけの補完が正解の曲もあり得る。今回未解決なのは、見送った区間が本当に補完不要なのか、推定器が追跡できなかっただけなのかである。

レポートのstatusは RENDERED_EXPERIMENT_NOT_QUALITY_APPROVAL。source_unchanged=true、winner_audio_modified=false、production_core_modified=falseと記録されている。今回はこれらを音声ファイルの独立再検証で再確認したわけではない。

## 2. 主な詰まりは追加量の最終制限より前にある

frame_reason_countsの合計は10,843フレーム。

| 最初に記録された判定理由 | フレーム数 | 全判定数に対する比率 |
|---|---:|---:|
| weak_periodicity | 6,821 | 約62.91% |
| transient_or_boundary | 3,387 | 約31.24% |
| eligible_tonal_interval | 390 | 約3.60% |
| existing_low_end_sufficient | 71 | 約0.65% |
| その他 | 174 | 約1.60% |

weak_periodicityとtransient_or_boundaryの合計は約94.14%。これは音楽そのものの客観分類ではなく、この版の判定器が最初に返した理由の構成比である。分析窓は192ms、間隔は20msで重なる。独立した10,843件の音符や、真の誤検出率として解釈しない。

ソースのanalyze_frameは、過渡的変化の判定、周期性、二つの分析帯域間の音高一致、倍音支持の判定を通過した後で、既存低域の量を判定する。したがって71フレームという値から、曲の99%以上で低域が不足しているとも、ほとんどの区間が補完不要だったとも言えない。量の判定へ届いていない区間が多い。

最初のscale=1.0がengineering_gate=trueで選ばれている。0.5や0.25への縮小は今回選択されていない。少なくとも今回の選択時間の短さを「最終ピーク上限のせいで大半が削られた」と説明することはできない。前段の認識・区間選択を先に点検する。

## 3. 配布版ソースから確認した、途切れを増やす構造

確認したソース：commit 2c9002fa842ce9d130c3c47df87246e871e3909a の note_sub_lab.py、analyze_frame / collect_frames / make_events / event_wave。

- 分析は完成2mixの中央成分に対する28〜750Hz、28〜260Hzの二つのフィルタ経路であり、楽器としてのベースを分離したものではない。
- make_eventsではamplitudeが0以下のフレームが一つ出ると、そこで連続区間を終了する。
- 連続区間が120ms未満ならshort_stable_runとして生成しない。
- 採用イベントの前後には各最大60msの内向きフェードを設けている。

以上から「一つの音符の途中でも、混合音の揺れでフレーム判定が落ちると区間が分断され、短い断片が捨てられる」という失敗経路は、コード上成立する。

ただし今回の実曲で、各棄却が本当の休符／発音境界だったのか、同じベース音の途中だったのかは、この集計だけでは確定しない。平均約0.198秒はベースの実際の平均音符長ではない。

## 4. 今回の音質判定

採用判断：未承認。Cを維持する。

支持されたこと：この実行で生成・測定・MP3出力まで進んだこと、およびレポートに記録された比較レベル／ピーク／帯域外エネルギーが設定内だったこと。

支持されていないこと：音高が正しい、演奏と自然につながる、リファレンスに匹敵する低域になった、艶や疲れなさが改善した、サブ補完という手法が無効だった、という各結論。

全曲RMSの微小変化は全曲平均についての観測であり、局所的な低域の可聴性を否定しない。追加レイヤーの全曲RMSには追加しなかった時間も含まれる。平均値だけで「絶対に聴こえない」と判定しない。

この段階で全曲A/Bの反復試聴を利用者へ要求しない。限定箇所での作用確認と、曲全体の完成度比較を混同しない。

## 5. 次の設計対象

まず音高・発音区間の推定を改善する。既存の19区間へ単純に大きなゲインをかけること、周期性の閾値を一律に緩めること、適用率の数値目標に合わせて休符を埋めることは採らない。

次版の設計案は、分析用のベース候補抽出、音符単位の時間追跡、追加の必要量判定を分離すること。短時間の分析不確実性と、実際の休符・音程変更を同じゼロ状態で潰さない。一方、前後が似ているだけで実際の休符を補間してはならない。正解の分かる検証例と独立した候補照合を必要とする。

出音は引き続き元Cと追加サブだけとし、分析用の分離音でボーカルやミックス全体を置き換えない。特定の分離モデル／実装方式を今回導入済みとは扱わない。

## 6. 今すぐ必要な一つの資料

SUB_REPORT.jsonには、採用した19イベントの時刻・音高の詳細が含まれていない。rejected_runsは採用イベント一覧ではない。前回「このJSONで追加音高を確認する」と案内した点は不十分だった。

次に必要なのは、同じRESULTフォルダに既に生成されたNOTE_EVENTS.json一つ。再レンダリング・設定変更・音符の手入力は不要。

NOTE_EVENTS.jsonから採用区間の時刻・長さ・音高軌道を確認し、候補として不自然な跳躍や断片化の兆候を点検する。JSONだけで実演奏に対する音程正答を証明できるわけではない。聴感の確認が必要なら、全曲ではなく判別に必要な区間へ絞る。

## 7. 今回変更したもの／変更しなかったもの

変更：本Markdownの判断記録のみ。
不変：C、DSPコード、閾値、ランチャー、本番runtime、既存音声。
実施していない：追加音の聴取、音声再測定、新方式の実装、CI再実行。
