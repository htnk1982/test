# PDRM Note-Sub v0.2.1 — 実曲ブラインド判定

日付: 2026-09-05  
状態: `CURRENT_TRACK_LISTENING_WINNER_ACCEPTED / NOT_PRODUCTION_DEFAULT`  
対象: Round9採用C = HarmonicElasticity に Note-Sub v0.2.1 を適用したブラインド比較  
変更範囲: この決定記録のみ。採用C、本番DSP、pdrm_engine、pdrm_runtime、pdrm_operator_lab は変更しない。

## 1. 利用者のブラインド判定

利用者回答: **Bが良い**。

ブラインド生成コードは `names=['CONTROL_C','SUB_AUGMENTED']` を初期順序とし、入力SHA-256の先頭1byteを整数化した値が奇数の場合のみ順序を反転する。

今回の採用C SHA-256は:

`ee2df798b8a3096bba078968c0db9e953769a42924f717de02f9107936e4e7d1`

先頭byte `ee` = 238 は偶数なので反転されない。従って今回の対応は:

- A = `CONTROL_C`
- B = `SUB_AUGMENTED`

よって、**今回の曲では Note-Sub v0.2.1 追加版が元Cより利用者の聴感選好で勝った**。

## 2. ここから確定してよいこと

- v0.2.1の低域補完仮説は、合成試験だけでなく今回の実曲でも知覚的便益を示した。
- 今回の曲については `SUB_AUGMENTED` を次工程の比較基準候補として扱う。
- 同じCに対して追加量をさらに増やすことを次工程にはしない。
- v0.1.1イベント監査へ戻らない。

## 3. まだ確定してはいけないこと

- 別曲でもv0.2.1が勝つこと。
- Note-Sub v0.2.1をproduction runtimeの既定処理へ入れてよいこと。
- Bが参照音源との差を全体として解消したこと。
- 低域以外の旧Cの差が、Bでも同じ強さで残っていること。

1曲での勝利は、曲固有の採用根拠にはなるが一般性能の証明ではない。

## 4. 次の問い

旧Cに対して『次に何を足すか』ではなく、

**Note-Sub適用後のBを新しい現在地として、参照との差のうち何がまだ知覚上・測定上残っているか。**

を確認する。

この確認は旧監査の反復ではない。処理対象そのものがCからBへ状態変化したため、次の介入を選ぶための新観測である。

## 5. 次の実行

チャット側へ `SUB_AUGMENTED.wav` だけを渡し、旧 `REFERENCE_GAP_REPORT.json` に保存された参照分布と同じ定義でBを測る。

追加の `SUB_REPORT.json`、`NOTE_EVENTS.json`、doctor、selftestは要求しない。

Bの測定後は、旧Cとの差と参照との差を分け、次の一作用だけを選ぶ。低域補完の勝利によって既に縮んだ差を再び攻撃しない。

## 6. 一般化の保留ゲート

Note-Subをproduction既定へ昇格する前に、今回を含め最大3曲の有限ブラインド比較を行う。追加2曲で以下を見る。

- 誤音・休符追加などのhard failureがない。
- 元C相当との比較で、追加版が勝つか少なくとも明確に悪化しない。
- hard failureが1曲でも出た場合は既定処理へ昇格しない。

これは一般性能の統計的証明ではなく、1曲成功を即座に本番既定へ昇格させないための最小ゲートである。

## 7. 現在の結論

**Note-Sub v0.2.1は今回の曲で採用。production defaultへの昇格は保留。次の開発対象は、Bを現在地として再定義する。**
