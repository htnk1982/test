# PDRM OPPO v3.1 — 高クレスト局所ピーク対応

日付: 2026-09-06

## 何を直したか

v3.0では、42.67ms窓内の変更可能量を「1ms局所RMS×0.8」でサンプルごとに固定していた。そのため、エネルギーは短いのに瞬間振幅だけ高いピークでは、聴感差分の全体量が小さくても、必要最小限のピーク修正量がこの局所上限を超えた時点で不成立になった。

利用者の24曲バッチで `Residual budget cannot fit this peak` が複数曲の早い時点に発生したため、曲別例外ではなくこの制約を修正した。

v3.1は**v0.1で選好されたソルバーを最初に必ず実行**する。旧ソルバーが成功する窓では計算結果を変えない。旧ソルバーが正確に `Residual budget cannot fit this peak` で止まった窓だけ、追加のFeasibility Rescueへ送る。

## Rescueの考え方

旧上限を無条件に緩めるのではない。

1. 指定ピーク上限へ入るために、そのサンプルで最低限必要な修正量を計算する。
2. その必要量が元ピーク振幅の60%を超える場合は救済しない。
3. 必要ピークの前後2.5msだけ、旧予算を超える波形差分を置ける余地を与える。
4. その余地は周辺振幅の40%を上限とし、実際に使う差分量は従来と同じ周波数・時間・ステレオ目的関数で最小化する。
5. 救済窓単体でも差分RMSとエネルギー変化を検査する。
6. 全曲合成後は従来と同じ全曲残差、帯域レベル、20ms包絡、M/S、無音保持のゲートを通す。

したがって、「通らないから0.8を1.5にした」という変更ではない。ピーク条件を満たすための**必要最小修正量**と、自然さのための**変更コスト・全曲ゲート**を分離した。

Rescueにも不成立条件がある。ピーク修正量が大きすぎる、局所差分・エネルギー変化が上限を超える、全曲の自然さ代理ゲートを超える、LUFS/TPが有限回で収束しない場合は完成出力を作らない。通常リミッター、クリッパー、互換前段への自動切替、目標LUFSの勝手な引下げは行わない。

## 選好済み音との関係

過去の24秒X/X比較で旧ソルバーが成立した窓は、v3.1でも旧ソルバーをそのまま使う。新Rescueは旧方式が局所予算不足で不成立だった窓だけに追加される。

したがって、**以前聞いたXそのものの計算を全面的に置換する版ではない**。一方、Rescueが実際に発動した窓の音は以前の試聴対象ではないため、その部分まで本人の聴感承認済みとは扱わない。実行記録にはRescue窓数を残す。

## 前段

v3.0同様、標準は「一定ゲインのみ（前段リミッターなし）」。HarmonicElasticity → 一定ゲイン準備 → Note-Sub → HFTC → OPPO v3.1。

旧前段ピーク整形は、処理前にGUIで明示選択する互換モードとして残す。失敗後に自動で切り替えない。

## GUIと出力

WAV/MP3それぞれのLUFS-I・True Peak上限を指定できる。初期値はWAV −12 LUFS / −2 dBTP、MP3 −14 LUFS / −2 dBTP。

出力は元ファイルの隣の `processed` に同名で保存する。

```text
元フォルダ/
├─ 曲名.wav
└─ processed/
   ├─ 曲名.wav
   ├─ 曲名.mp3
   └─ .pdrm/
```

設定変更して再作成するときは、GUIの管理済み旧出力退避を選ぶ。元音源・手動編集した出力・管理記録のない同名ファイルは上書きしない。

## 配布

Windows x64向けPyInstallerフォルダ配布。ZIP全体を展開して `PDRM_OPPO.exe` を起動する。EXE単体を抜き出さない。Python/FFmpegの追加インストールは不要。コード署名なし。

## 検証範囲

- 選好済み `offline_peak_lab.py` とv3.0 `offline_peak_stream.py` は変更しない。
- 旧ソルバー成功窓がv3.1でサンプル完全一致する回帰を持つ。
- 旧局所予算で不成立になる狭い高クレスト波形をRescueで処理する回帰を持つ。
- 60%瞬間書換え上限、局所差分ゲート、正確なモノ/逆相、無音ロック、途中再開、入力非破壊、通常リミッター不使用を検査する。
- 全曲自然さの保証、全ターゲット組合せの成立、全再生系のTrue Peak保証ではない。

24曲の実ファイルは利用者PC上にありCIへアップロードしていないため、今回のビルドだけで24曲全件成功を主張しない。同じ失敗型を解消した版として、次の実バッチ結果で適用範囲を確定する。
