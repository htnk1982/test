# PDRM 配信用仕上げ v2.1 — 元フォルダのprocessedへ同名保存

日付: 2026-09-05

## 保存する場所と名前

元ファイルの隣に `processed` フォルダを自動作成します。ファイル名の本体はそのまま保ち、拡張子だけ `.wav` / `.mp3` にします。

```text
音源フォルダ/
├─ 06 - 03 返事は私.wav             ← 元音源・変更しない
└─ processed/
   ├─ 06 - 03 返事は私.wav          ← −12 LUFS、TP上限−2 dBTP
   ├─ 06 - 03 返事は私.mp3          ← −14 LUFS、320kbps
   └─ .pdrm/                       ← 再実行・衝突確認用の小さい管理記録
```

日本語・空白・途中のドットを維持します。`_12LUFS` 等の接尾辞や、曲別のハッシュ名フォルダを完成音の名前に付けません。FLAC入力も `元の名前.wav` と `元の名前.mp3` になります。複数の場所から選んだ場合は、それぞれの元フォルダにprocessedを作ります。保存先選択ダイアログはありません。

## 導入と実行

1. ZIPを展開します。
2. `pdrm_processed.cmd` と `PDRM_Processed_v2_1` フォルダを、現在使えている `.venv` と同じ階層へ置きます。既存のcmdやPythonファイルは置換しません。
3. 今後は **pdrm_processed.cmd** をダブルクリックし、未処理のWAV/FLACを選択します。複数選択できます。ファイルをcmdへドラッグ＆ドロップしても使えます。

新しい依存ライブラリの追加やpip実行はありません。旧版の起動cmdでは保存方式は変わらないので、今回のcmdを使用してください。

## 維持する音声処理

最新の `distribution_finish.py` v2.0をそのまま呼び出します。

**HarmonicElasticity → 共通ピーク整形 → Note-Sub v0.2.1 → HFTC v0.1 → 配信用ゲイン・ピーク調整**

HarmonicElasticityとピーク処理を含みます。旧Accepted Finish v1／Release Finish v1.1の追加2段専用入口とは区別してください。新しい音色調整や閾値変更はありません。旧3曲試聴の未記録ピーク処理を再現したという意味でもありません。

- 公開WAV: −12 LUFS-I（許容±0.03 LU）、True Peak数値推定上限−2 dBTP、24-bit PCM、元サンプルレート。
- MP3: 完成−12 WAVから一定ゲインで作った内部−14 WAVを符号化。320kbps、復号後の−14 LUFS（許容±0.10 LU）とTP上限−2 dBTPを検査。
- 内部の−14 WAVは完成フォルダに追加しません。完成フォルダへ出す音声は同名WAV・MP3の2本です。
- ファイル保存部は、検査済みの完成音をバイト単位でコピーするだけで、再エンコード・再量子化しません。

元サンプルレートは44.1/48/88.2/96 kHz。高レート入力のMP3は既存v2の規則どおり48 kHzへ変換します。True Peakは既存の補間による数値推定であり、認証測定器の保証ではありません。

## 再実行と同名ファイル

元音源は上書きしません。同じ入力・同じ処理版・同じ実行条件の再実行は、管理記録と出力ハッシュが一致すれば再処理せず完了扱いになります。

既存出力を編集した場合、管理記録のない同名ファイルがある場合、または同じ名前で入力の内容が変わった場合は上書きせず止めます。新しい内容を保存する際は、元の入力を別名にするか、既存のprocessedフォルダを退避してから元入力を再実行してください。

同じフォルダの `曲.wav` と `曲.flac` は同じ出力名になるため、同時選択した場合は処理前に衝突を通知します。`processed` 内の出力を再び入力にすることは禁止し、`processed/processed` を作る重ね掛けを防ぎます。

WAVとMP3の2本を一つのファイルシステム操作で同時保存するわけではありません。各ファイルは検査済みの一時コピーから公開し、その間で中断した場合は管理記録を使って不足した方だけ復旧します。処理済みファイルを他の内容で上書きして救済しません。

## 作業記録の所在

内部レンダリング・中間音声・詳細検査は `%LOCALAPPDATA%\PDRM_Local_Render_Engine_v1\processed_finish_v2_1` に保存します。利用者へのJSON提出依頼ではありません。processed内の `.pdrm` は完成2本の整合確認用です。

## この版で変更した範囲

追加: `processed_finish.py`、起動cmd、25件の保存/接続テスト、ガイド、専用CI。
未変更: distribution_finish、distribution_peak、accepted_finish、Note-Sub、HFTC、本番runtime。

音声の採用判断は再審査しません。新しいテストは日本語名・同名衝突・再実行・中断再開・元音保護・コピー同一性・入出力接続の確認です。

技術根拠: Python公式 `os.rename` / `os.link` の仕様。Windowsでは既存宛先を置換しないrenameを使用。POSIXではno-clobber linkを使用し、未対応ファイルシステムは上書きにフォールバックせずエラーとします。
