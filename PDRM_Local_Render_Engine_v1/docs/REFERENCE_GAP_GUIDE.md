# PDRM — Cを変えずにリファレンスとの差を測る

## 使い方
既にRound9が動くフォルダへ `reference_gap.py` と `reference_gap.cmd` を追加します。本番core、runtime、Round9出力を上書きしません。setup、doctor、既存acceptanceの再実行は不要です。

`reference_gap.cmd` をダブルクリックし、次の順に選びます。
1. 今回試聴した `Round9_Output/ Round9_... / manifest.json`
2. 以前から使っている `ConfidenceBoost.wav`

CのWAVはmanifestと同じjob内から自動で特定し、既に監査したCのファイルSHA-256と照合します。Cそのものへ追加処理はしません。CのMP3を再処理することもありません。

画面には2秒間隔で工程、進捗、経過秒、直近の工程更新からの秒数を表示します。heartbeatはプロセスの生存表示であり、DSPの進捗保証ではありません。最後に `REFERENCE_GAP_REPORT.json` のパスを表示します。出力先は原則 `%LOCALAPPDATA%/PDRM_Local_Render_Engine_v1/reference_gap/` です。

このJSONだけで次の分析を進めます。今回、追加試聴やA/B/C順位づけは不要です。

## 何を比較するか
両方の音源へ同じ数式・同じ実時間窓を使い、30秒ずつ読み取ります。音声ファイルは生成しません。

- 100/400msのピーク対RMS関係
- 20Hz〜20kHzの10帯域の平均エネルギー
- 帯域別100/400msパワー分布（P10/P50/P90）
- 各帯域P90から6dB以内に存在する時間割合（独自の占有率指標）
- 3秒RMSの変動、Mid/Side電力比
- 4倍FIRによるTP推定、ブロックPLR

帯域値はL/Rのパワーを別々に求めて平均します。先にモノラル化して逆相成分を消す測定にはしません。

## 解釈上の制限
**これは一度の粗い現状比較です。疲れなさ・艶・主観的大きさの直接測定ではありません。数値が参照と違うだけで加工すべきとは判定しません。**

各30秒ブロックは分析上のみ−14 LUFSへ揃えます。この操作でブロック間の元の音量差を除くため、Spotify等の曲単位正規化の模倣ではありません。元ブロックのLUFSと補正量も別欄へ保存します。

参照録音の曲境界が現在確認できていないため、13曲として自動推定・再ラベルしません。固定時間窓の分布であり、曲の切替をまたぐ窓も、旧資料で補助に回した14曲目も含まれ得ます。1曲ごとの均等比較ではなく時間に比例した標本です。旧PLR/crestのhard_maxは一切使いません。

10秒未満の末尾および−60 LUFS未満の窓は除外し、理由を記録します。残りは選り好みせず全窓を保存します。必要なら結果のタイムスタンプから後で特定区間を区別でき、現段階で何度も条件を変えて計測しません。

本ツールのcrestは実サンプルレートから100/400msを作る新しい同一定義です。旧コードにあった44.1kHzでの1ms=44サンプル換算と一致しないため、旧閾値や旧測定値との直接判定は禁止します。

帯域占有率は常時鳴る音と短い音の違いを見る記述指標です。大きいほど良いわけではなく、音量が非常に小さい帯域ではnullを返します。

## 保存・再開
測定済みブロックはチェックサム付きJSONへ逐次保存します。同じ入力・コード・依存バージョン・設定なら再利用し、中断したブロックだけをやり直します。同じjobへの同時起動はOSロックで拒否します。SQLiteは使いません。

入力2ファイルのSHA-256を前後で確認します。比較出力を元Round9 jobの内部に置くことは禁止します。監査済みCのhashが違う場合、勝手な再生成や別曲への置換はせず停止します。

## できていないこと
この配布物だけで利用者のCとConfidenceBoostの実測結果が得られたわけではありません。ローカル実行後のJSONが必要です。CIの試験音は合成音であり、利用者の実音源を公開CIへ送っていません。
