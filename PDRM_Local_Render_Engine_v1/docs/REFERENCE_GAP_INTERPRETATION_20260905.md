# PDRM — C／ConfidenceBoost比較結果と次の実験範囲

日付: 2026-09-05  
状態: 提出レポートの読解・次工程の設計判断。新しい音源の生成やDSP実装ではない。  
主資料: 利用者が提出した `REFERENCE_GAP_REPORT.json`（reference-gap-1.0）

## 1. 結論

C＝HarmonicElasticityを採用基準として保持する。

今回の比較から、次の試作対象は『全帯域をさらに詰めること』ではなく、**既存の低い帯域の量と、それより上の帯域との関係**へ絞るのが妥当と判断する。

特に20〜60Hzのブロック平均エネルギーが参照分布に比べて小さい。一方、4〜16kHzには一様な平均量不足がなく、1.2〜4kHzはむしろ参照中央値より大きい。この構図は利用者の『低音の底が足りない』『明るくしても張りや艶にならない』という問題意識と整合するが、その聴感の原因を証明するものではない。

この文書は、レポートが自動で出した処方ではない。レポートに記録された観測から、次の可逆実験の優先順位を私が提案するものである。

## 2. 何を測定した資料か

- 対象C: 216.842秒、48kHz、ステレオ。採用されたCのファイルSHA-256と一致。
- Cの採用ブロック: 30秒×7。末尾6.842秒は `short_tail` として除外。
- 参照: ConfidenceBoost.wav、2742.950022675737秒、44.1kHz、ステレオ。92ブロックを計測。
- 各ブロックを分析上のみ−14 LUFSへ合わせる。これは全曲の再生レベル合わせやSpotifyの曲単位正規化の再現ではない。
- `source_unchanged = true`、`production_core_modified = false`。
- `status = MEASURED_NOT_QUALITY_APPROVAL`。測定完了であって、音質の合格判定ではない。
- 参照の曲境界は推定していない。曲切替をまたぐ区間と旧14曲目を含み得る。7対92は独立した7曲対92曲の比較ではない。

出典位置: `C`, `C.rows`, `reference`, `identity`, `source_unchanged`, `production_core_modified`, `status`, `inference_limits`。

## 3. 帯域平均エネルギーの比較

以下は各帯域のブロックRMSレベルの中央値。単位dBFS、各ブロックのLUFS補正後。

| 帯域 | Cの中央値 | 参照中央値 | C−参照 |
|---|---:|---:|---:|
| 20〜60Hz | −33.5474 | −23.7593 | **−9.7881dB** |
| 60〜110Hz | −25.9985 | −22.6389 | **−3.3596dB** |
| 110〜250Hz | −22.9322 | −24.3118 | +1.3797dB |
| 250〜500Hz | −26.6633 | −25.3261 | −1.3373dB |
| 500Hz〜1.2kHz | −23.1110 | −24.3537 | +1.2427dB |
| 1.2〜4kHz | −24.3162 | −26.4022 | **+2.0860dB** |
| 4〜8kHz | −33.3866 | −33.0503 | −0.3364dB |
| 8〜12kHz | −34.7948 | −35.3871 | +0.5923dB |
| 12〜16kHz | −39.9904 | −41.5566 | +1.5662dB |
| 16〜20kHz | −63.8317 | −50.2581 | −13.5736dB |

出典位置: `C_summary["band/<帯域>/rms_dbfs_at_anchor"].p50` と同名の `reference_summary`。差分はレポートの `C_minus_reference_median` と整合する。

各欄は別々に集計した中央値であり、10行を合わせた一つの実在する30秒区間のスペクトルではない。補正カーブとしてそのまま反転して使わない。

### 3.1 最下部の量は、優先して検討する根拠がある

20〜60HzのC中央値は−33.55dBFS。参照側P10でも−27.14dBFSなので、C中央値はこの下限目安より約6.40dB小さい。

20〜60Hzのパワー比率のブロック中央値も、Cが約2.07%、参照が約16.79%。ただし、これは個々の比率を集計した中央値であり、両音源全体の総エネルギー比率ではない。

この結果は『比較条件内でCの最下部は量が少ない』を支持する。しかし『失われた低域を復元できる』『参照との差と同じ9.8dBを足すべき』を支持しない。曲の最低音、音色、キックの音程、編曲、上流処理などの原因は未分離である。

### 3.2 低域全部を一括して扱わない

60〜110Hzは小さい側、110〜250Hzは大きい側、250〜500Hzは再び小さい側である。

『低音不足だから低域全体を増やす』『もこもこするから200〜500Hzを広く削る』という一括処方にはしない。250〜500Hzは参照中央値より少なく、この比較だけでは広く削る根拠にならない。

### 3.3 16〜20kHzの差は別問題として保留

16〜20kHzの差は約−13.57dBと大きいが、当該帯域のパワー比率中央値はC約0.00210%、参照約0.03649%。大きな相対dB差と、信号全体に占める量を混同しない。

これだけで『艶は16kHz以上を増やせば戻る』とは言えない。音源自体、過去の処理、非可逆圧縮等のどこで差が生じたかも今回のJSONでは特定できない。既存のR9経路監査を再び無期限に開き直さず、この帯域の補完・新規成分生成は次の試作から外す。

## 4. 密度は一方向に不足しているわけではない

### 4.1 最下部を長く鳴らすべきとは、まだ言えない

20〜60Hzの400ms占有率中央値は、C約78.44%、参照約73.05%。60〜110HzもC約87.25%、参照約77.42%。

これは『各帯域・各ブロック内のP90から6dB以内にある時間割合』であり、絶対的な音量や楽器の発音時間ではない。それでも、平均量が小さいことだけから『持続を長くすればよい』へ進む根拠はない。

次の試作では、低域の残響・sustain延長を最初から混ぜず、既存の発音区間内の量だけを変更対象にする。

### 4.2 高域は、弱い時間帯にも成分が残る側

100ms帯域パワーの、各ブロック内P10とP90をそれぞれ集計した中央値差:

| 帯域 | P10のC−参照 | P90のC−参照 |
|---|---:|---:|
| 8〜12kHz | +6.2068dB | +0.0294dB |
| 12〜16kHz | +8.1212dB | +0.8056dB |

100msの帯域内P90−P10の中央値も、8〜12kHzではC10.2266dB／参照16.6150dB、12〜16kHzではC10.5362dB／参照17.7503dB。

この観測は、Cの高域が単純に弱いというより、相対的に弱い時間帯にもエネルギーが残る方向を示す。『無音が失われた』『ノイズが多い』『ハイハットの処理が失敗した』までは特定できない。ハイハットのパターンや音色、編曲も代替説明である。

次の試作では高域への一律の明るさ・小信号促進を加えない。高域のコントラスト処理は別の仮説として保留する。

出典位置: `C_summary`／`reference_summary`の該当帯域、`100ms/p10_dbfs_at_anchor`, `100ms/p90_dbfs_at_anchor`, `100ms/p90_minus_p10_db`, `400ms/occupancy_6db_below_p90`。

出典位置: `C_summary`／`reference_summary`の `block_plr_tp_db`, `crest_100ms_p50_db`, `crest_400ms_p50_db`, `crest_100ms_p95_db`, `crest_400ms_p95_db`, `rms3s_p90_minus_p50_db`, `ms_power_ratio_db`。

Cは参照中央値よりピーク対平均が大きく、Mid優勢である。ただし多くの指標は参照P10〜P90内。100ms crest P50も参照P90を約0.082dB上回る程度であり、境界を少し超えたという理由で不良判定しない。

ここでのP10〜P90は記述的な区間であり、品質の許容範囲、信頼区間、統計的有意差ではない。92ブロックを独立した92曲として扱わない。

crestはピークだけでなく分母のRMSでも変わる。そのため、帯域構成が異なる二つの音を比較して、crest差の全量をピーク過剰へ帰属しない。次の実験は全帯域のlimiting、macro flattening、stereo wideningを含めない。

## 6. 次の実装対象案：低域下部の存在量だけを切り分ける

仮の実験名: `Low-Register Foundation`。

**問い:** 採用Cの中高域、ボーカルの位置、リズム、反復試聴の快適さを保ちながら、既存低域の下側の量を増やすと、『土台の薄さ』が改善するか。

比較はCと処理案の二つを基本にする。Cは不変の対照として保護する。採用済みHarmonicElasticityの重ね掛けは行わない。

設計上の範囲:

- 20〜110Hz内に元から存在する成分を対象とする。20〜60Hzと60〜110Hzは分けて評価し、110Hz以上を一括増強しない。
- オフラインで前後の文脈と元の発音区間を参照する。無音・成分不在箇所を埋めない。周波数移動や新しい音符、サブハーモニクスは生成しない。
- 最初は発音区間内の振幅関係の変更だけに絞る。sustain延長、attack移動、HF処理、Mid/Side配分変更は同時に加えない。
- 参照中央値への一致を最適化目標にしない。9.8dB差をそのままブースト量に変換しない。
- 初期試作は小さい変化から探索する。以前許容された1dB前後の長期音色変化を最初の尺度とし、正確なマスク形状・局所上限・時間幅は実音源上の処理と検証で定める。このJSONだけで最適値が決まったとはしない。
- 処理後は全曲LUFSを比較基準へ合わせる。今回の30秒ごとの分析用正規化を、音源レンダリングへ持ち込まない。
- ピーク安全性、有限値、長さ、無音保持、L/R共通の制御、ブロック継ぎ目、MP3復号後レベルを機械検査する。安全制約を破った候補へ、無断でlimiterを足して救済しない。
- 過剰な低域、濁り、ボーカル後退、キック／ベースの分離悪化、疲れの増加が出た場合はCへ戻す。差が分からない場合も自動採用しない。

これは『新しいマスタリング原理の完成』ではなく、今回の大きな未確定を一つだけ動かす可逆実験の設計である。日常の製品運用に毎曲A/B/C選択を要求する方針ではない。

## 7. 三つの視点による裁定

### 音響設計

低域下部を最初の試作対象にすることに賛成。全帯域の密度向上を繰り返すより、現在の測定差と接続している。ただし既存の20〜110Hzを広く持ち上げるだけで良いとは限らない。

### 検証

優先順位には条件付き賛成。20〜60Hzの差を聴感上の原因と断定せず、参照の編曲・音程の違いを残す。高域は平均量より分布の違いが検討対象だが、今回は二つ目の処理を混ぜない。

### 実装・利用負担

再測定ツールの追加より、上記一作用の試作へ進むことに賛成。Cの完全保持、production層との分離、失敗時に戻す条件を維持する。利用者に環境再設定や同じ測定の再実行を要求しない。

## 8. 合意・未決・次の一手

### 3人が合意できたこと

Cを維持し、今回の比較は終了する。全帯域の密度・高域量をさらに増やす方向へ自動進行しない。次の試作の第一候補は既存低域下部の量であり、参照のEQコピーではない。

### まだ揉めている論点

低域差のうち、どこまでが望ましい編曲・音色の個性で、どこまでが改善可能な薄さか。低域の変更が同じLUFSで張り・大きさ・快適さを実際に改善するか。今回の集計だけでは決まらない。

### 私が決めなければいけないこと

このレポートを受け取る段階で、利用者に追加の測定・試聴・再設定は要求しない。次の音源を評価する段階では、数値では置き換えられない選好だけが残る。
