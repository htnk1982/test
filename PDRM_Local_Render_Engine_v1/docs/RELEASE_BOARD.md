## 6. 管理と実行の規則

- 主タスクの仕掛かりは1件。受入失敗ならそのタスクを修正し、成功証拠を持って閉じる。
- DONEは、対象・commit・実行環境・結果・非対象を必須にする。子の閉鎖で親全体を閉じない。
- 各報告は、**今回閉じたID / 残る阻害要因 / 次の実行ID / 成果物**を固定の入口とする。
- 新LAB・指標を増やす場合は、閉じる既存課題IDを明示する。機能研究そのものを進捗の代用にしない。
- 試験数、管理資料数、コード量を完成率にしない。仕様縮小で項目を消す場合は解決でなくscope changeと記録する。
- 課題が増える場合は理由とゴールへの影響を記録する。発見を隠すために分母を固定しない。
- P01不通を「安全のため後回し」と言い換えない。復旧時は実曲による判断・校正を優先し、運用改修を延々と代わりに進めない。
- 所有・機密条件が未確認の外部実行へ私有音源を送らない。現在の障害は音源再提出で解決すると決めつけない。
