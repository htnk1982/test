## ゴールと固定条件

元WAV/FLACを選ぶと、音楽的に必要な補強と整理を自動判断し、GUI指定のWAV/MP3別LUFS・TPで、元フォルダの`processed`へ同名音声を保存する。原音・既存の良好な中高域・必要な低域の強さを保護し、必要以上に持続する音や誤生成を抑える。通常終了/失敗/中断の後始末を実装し、更新Windows EXEを実曲で受け入れる。

HE/HFTC/OPPO本体の大改造、新規octave-down、速度だけを目的とした再研究は今回の目標に追加しない。一方、同一基音の補強や本来の音楽的効果を無言で省いた限定版を完成扱いにしない。故障した原音を『元からだから』と放置する仕様にはしない。

完了条件:

- 同じ要求では再処理しない。設定変更時は明示的な退避指定が必要。

## 進める順序と打切り条件

最短の機能経路: **P01/P02 → P03 → P04 → P05 → P08**。
独立して進められる運用経路: **P07-A → P07-B/P06 → P07-C → P08**。
P01不通を『安全のため実曲は後』に言い換えない。実曲検証が止まっている事実を各報告に残す。環境を短く再確認して不通なら、その会話では無駄な再試行を止める。代替の実行場所にデータ送信が必要なら、権限と機密の条件を確定せず実行しない。

仕掛かりは主タスク1件。必要な環境・モデル確認は阻害要因を解く作業としてのみ並行する。新しい指標/LABの追加は、どの固定IDを閉じるためかが説明できなければ着手しない。時間見積で完成日を捏造しない。

## 完了・進捗を偽らない規則

- 管理基盤や試験数の増加を製品完成率へ加算しない。
- DONEには対象、commit、実行環境、結果、残る非対象を添える。証拠なしにIssueを閉じない。
- 親は全受入条件がそろってから閉じる。子タスク完了は親PARTIALのままでもよい。
- 失敗・新たな阻害要因・再開した課題は消さず差分履歴に残す。
- 仕様変更で課題を取り除く場合はscope changeと記録し、解決数を増やさない。
- チャット報告は『今回閉じたID／残る阻害要因／次に実行するID／新しい成果物』を中心にする。
