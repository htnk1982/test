# PDRM 配信用仕上げ — Windows EXE版

## 実行するもの

ZIP全体を展開し、`PDRM_Processed.exe`をダブルクリックしてください。
Python、仮想環境、FFmpeg、pipのインストールは不要です。管理者権限も通常は不要です。

これは単独EXEへの全ファイル埋め込みではなく、PyInstallerのフォルダ配布形式です。
**EXEだけを取り出さず、同梱の`_internal`、`LICENSES`、`SOURCES`を含めてフォルダごと配布してください。**

## 使い方

1. `PDRM_Processed.exe`をダブルクリックします。
2. 未処理のステレオWAV/FLACを選びます。複数選択できます。
3. 処理終了後に開く`processed`フォルダを確認します。

音源をEXEへドラッグ＆ドロップする方法でも使えます。

```text
音源フォルダ/
├─ 曲名.wav                   元音声は変更しない
└─ processed/
   ├─ 曲名.wav                −12 LUFS、TP上限−2 dBTP、24-bit PCM
   ├─ 曲名.mp3                −14 LUFS、320kbps
   └─ .pdrm/                  再実行・衝突確認の管理記録
```

複数フォルダの音源は、それぞれの元フォルダ内へ保存します。
MP3は完成した−12 WAVから一定ゲインで作った内部−14 WAVを符号化します。

## 処理内容

HarmonicElasticity → 共通ピーク整形 → Note-Sub v0.2.1 → HFTC v0.1 → 配信用ゲイン・ピーク調整。
元v2.1の7個のPythonモジュールは変更していません。EXE用の起動と資源同梱を追加しています。

同梱FFmpegは7.1.5の音声専用LGPL構成を対応ソースからビルドしたものです。
これまでPATH等から選ばれていた外部FFmpegと同一のバイナリではありません。
ネットワークプロトコル・動画処理・GPL/nonfree機能を無効化しています。
処理規則は維持し、EXEとソース版に同じ同梱バイナリを使用する回帰試験で確認します。
従来の任意バージョンのFFmpegと全出力がビット一致するとは主張しません。

## 保護と注意

元音声・既存の別内容の同名出力は上書きしません。同じ処理済みファイルを再投入しないでください。
元音源からの再実行は、実行条件と出力が一致すると処理を省略します。
旧版の出力が既にprocessed内にある場合、処理条件の違いで停止することがあります。
その際は旧processedフォルダを別名で退避し、元音源を選んでください。

内部キャッシュとログはユーザーのLOCALAPPDATA下に保存します。起動フォルダへ書き込む必要はありません。
長い音源は中間WAVを保存するため、入力ファイルの数倍以上の空き容量を確保してください。

このEXEには発行者のコード署名がありません。WindowsのSmartScreenや組織の管理ポリシーにより警告・実行拒否される場合があります。
保護機能を無効化せず、入手元・同梱SHA-256を確認してください。管理下のPCでは組織の許可に従ってください。

## 配布者向け

Windows x64向け。Windows 10/11での利用を想定し、実際に検証したOSは同梱BUILD_REPORT.jsonを参照してください。
Mac・32-bit Windows用ではありません。
本体の処理はオフラインです。ビルド時だけ依存ライブラリ・ソース取得の通信を行います。
同梱ライセンスと第三者ソース・再ビルド手順を削除しないでください。
署名証明書と販売用インストーラーは含みません。

## 再ビルド

リポジトリの`.github/workflows/pdrm-windows-exe.yml`と`packaging/`を参照。
Windows上でPyInstallerを実行し、生成物をビルドツリー外へコピーして検査します。
音声は合成試験信号のみをCIへ使用し、利用者の楽曲をGitHubへアップロードしません。
