# PDRM v2.2 — WAV・MP3のLUFS／True PeakをGUIで指定

## 起動と操作

ZIPをすべて展開し、`PDRM_Processed.exe`をダブルクリックします。
最初の画面でWAVとMP3の4項目を指定し、「この設定で開始」を押して元のWAV/FLACを選択します。複数曲を選べます。音源をEXEへドラッグした場合も、処理前に設定画面が出ます。
Python、pip、FFmpegの追加インストールは不要です。

| 出力 | 初期LUFS-I | 初期True Peak上限 |
|---|---:|---:|
| WAV | −12.0 LUFS | −2.0 dBTP |
| MP3 | −14.0 LUFS | −2.0 dBTP |

0.1刻みの上下ボタンと直接入力が使えます。LUFSは−30〜−8、TP上限は−12〜−1 dBTPの範囲です。無効値・空欄・NaN等では処理を開始しません。
最後に開始した設定はユーザーのLOCALAPPDATA内に保存し、次回起動時に復元します。「初期値に戻す」と「キャンセル」もあります。設定画面を閉じただけでは音声処理を始めません。

TPは上限です。ピークを指定値まで無理に増幅する目標ではありません。
高いLUFSと低いTPを同時に指定すると、ピーク圧縮が増える場合があります。数値条件の達成は音質の保証ではありません。処理が所定の試行数で目標に到達しないときは、別の音量で黙って保存せずエラーにします。

## 音声処理

HarmonicElasticity → 共通ピーク整形 → Note-Sub v0.2.1 → HFTC v0.1 → 指定したWAVのゲイン・ピーク仕上げ。
HarmonicElasticityの伝達関数、Note-Sub・HFTC、前処理の−14 LUFS／−2.5 dBTP条件は維持します。GUIの4項目は最終出力の条件で、音符検出や高域減衰の強度を変更しません。

MP3は完成したWAVから専用の内部WAVを作って符号化します。定数ゲインでMP3目標を満たせる場合は追加リミッターなしです。MP3側をより大きくする、またはピーク上限を厳しくする場合は、必要に応じてMP3側だけをピーク処理します。完成WAVは変更しません。
符号化後にMP3を復号し、指定LUFSとTP上限を確認します。目標と計測値は各出力の管理記録に残します。LUFSの検査許容は±0.03 LU、TPは4倍・8倍補間の大きい推定値を使用します。認証測定器との完全一致は保証しません。
厳しい出力条件でのゲイン探索のみ、測定された応答から入力ゲインの更新幅を求めるよう改善しました。リミッターの種類・先読み・リリース時間は変えていません。

## 出力先

```text
音源フォルダ/
├─ 曲名.wav                  元音源を保持
└─ processed/
   ├─ 曲名.wav               指定LUFS・TP、24-bit PCM
   ├─ 曲名.mp3               指定LUFS・TP、320kbps
   └─ .pdrm/                 整合記録・必要時のバックアップ
```

WAVのサンプルレートは入力を維持します（44.1/48/88.2/96 kHz）。高レート入力のMP3のみ48 kHzへ変換します。

## 同じ曲を設定変更して再出力する場合

設定画面で **「既存のPDRM出力を退避して、同じ名前で作り直す」** をチェックします。
新しい音源の描画・検査に成功した後、以前の同名WAV・MP3を `processed/.pdrm/backups/` に保存してから新しい出力を公開します。
以前のPDRM管理記録とハッシュが一致する出力だけが対象です。元音源、手動編集したファイル、管理記録のない同名ファイルは上書きしません。同じ名前で元音源の中身が変わった場合も自動置換しません。
同じ入力・設定の再実行は照合してスキップします。設定値は実行識別子とキャッシュ判定に含めているため、変更前の出力を新設定の結果と誤認しません。

## 配布

EXE単体ではなく、`_internal`、`LICENSES`、`SOURCES`を含むZIP全体を配布してください。単一ファイル埋め込み形式ではありません。旧版へ混ぜて上書きせず、新しいフォルダへ展開します。
本体はWindows x64用、オフライン処理です。コード署名はありません。Windows／組織の保護機能を無効化しないでください。
同梱FFmpegと第三者ライブラリのライセンス・対応ソースは前版と同じ配布構成を維持しています。

## 実装・機械試験の範囲

GUI・設定保存・出力条件の受渡し・MP3分岐・再出力時の退避を追加しました。既存139件に28件の回帰を追加します。実際の実行数・成功は同梱SOURCE_TEST_RESULTS.jsonとEXE_SMOKE_RESULTS.jsonを参照してください。音楽の聴感採用をやり直す試験ではありません。
自動試験では実際のTk入力欄の検証・保存・復元・キャンセルを実行し、ビルド済みEXEで初期値と変更値の音声出力を計測します。利用者の音源はGitHubにアップロードしません。
